Local deepfake detection pipeline
This repository contains a consent-aware media manifest starter and dataset-independent detector tooling. It is for detection and research evaluation only. It does not generate or alter synthetic media.
No license has been selected for this project's source code. Dataset licenses are separate and do not grant rights to this code or to underlying source media; choose a project license before presenting a public GitHub repository as open source.
One-command run
The runner calls the same individual stages in order and stores their outputs together. Provide a completed dataset card and use a new or empty output folder. Add --inference-input when you also want to score unseen media after training.
​
The run folder contains the ingestion manifest, combined prepared frames, group splits, readiness report, model, validation and test predictions, validation-selected threshold, and test evaluation. The runner defers test metrics until after threshold selection. Optional unseen-media predictions are written to inference_predictions.jsonl. The runner exits if a stage fails; review that stage output before starting a new run folder.

Cloud dataset intake
The acquired Mendeley archives are in the user's Google Drive Datasets folder. The central-directory inventory has already been inspected remotely without reading the media payloads; see the dataset cards for observed counts and discrepancies. Do not run cloud_dataset_intake.ipynb just to see archive counts: it downloads and extracts the media, which can take a long time. Use it only when you are ready to materialize the full dataset in Colab for checksum-verified processing.
The SDFVD 2.0 Colab workflow generates provenance-rich metadata from the real/fake folders and filename conventions. It groups the real vN source with its face-swapped vsN counterpart and all augmentations, then keeps each pair intact across data splits. This source-pair grouping is required because the dataset record says fake videos were made by face-swapping original source videos. The workflow stops on ambiguous labels and preserves the observed 927-video count against the published 922 for review.
Draft dataset-specific cards are in data_ingestion/dataset_cards/. The SDFVD2 card used for a run is generated from the observed inventory and records the CC BY 4.0 attribution and unresolved underlying source-media rights.

Audio-visual multimodal path
This is an implemented late-fusion prototype, separate from the ResNet frame baseline. For each consent-cleared video it extracts one frame and the first 8 seconds of mono 16 kHz audio, computes a 64-bin log-mel representation, then combines an image encoder and audio CNN. Videos with no decodable audio retain an explicit missing-audio flag. It does not crop faces, model long-range temporal changes, or claim validated accuracy. All training/evaluation numbers must come from an actual run on reviewed metadata and source-group-disjoint splits.
For SDFVD 2.0, use multimodal/run_pipeline.py --group-cv-folds 5 to estimate performance across five paired-source-held-out folds. Each fold uses separate validation groups for checkpoint/threshold selection. Report the per-fold mean and spread; do not pool probabilities from independently trained fold models. The cross-validation run produces five fold checkpoints, not one final deployment model. It estimates performance within this small dataset only. The vN/vsN pairing is a lineage inference from archive names and the published face-swap description; retain the metadata audit and verify this convention if publisher documentation becomes available. Prior runs split paired real/fake families and are invalid for paired-source-independent evaluation. All retained videos in those runs lacked decodable audio, so the fused branch was effectively video-only.

External visual evaluation on Comprehensive v3
multimodal/evaluate_external_frames.py evaluates the saved visual checkpoint from each SDFVD2 paired-source CV fold on a separate labeled image dataset. For each filename-derived candidate video stem, it selects one deterministic median-index face crop, resizes and normalizes it like the SDFVD2 visual branch, and reports each fold separately. It applies that fold's visual threshold selected from SDFVD2 validation predictions; it does not tune on the external dataset or pool scores from different fold models.

The current Comprehensive v3 archive inventory does not reconcile with the publisher's frame/video counts, and several filename-to-source mappings remain unverified. The resulting report is therefore explicitly marked provisional. Its candidate video units may also share underlying source videos, so they are not guaranteed to be independent observations. This evaluation measures the shift from SDFVD2 video frames to pre-cropped faces; it does not establish broad real-world generalization. Keep the Comprehensive dataset separate from SDFVD2 training until its labels, source lineage, duplicates, and usage rights are reviewed.
The first external run completed on 2026-10-16. Across the five fold models, mean ROC-AUC was 0.5248 (fold SD 0.0420) and mean balanced accuracy was 0.5116 (SD 0.0072), both near chance. Mean accuracy was 0.6967 (SD 0.2322), but is misleading because the 900 filename-derived candidate units include 870 synthetic and only 30 real examples. Per-fold ROC-AUC values were 0.5423, 0.5897, 0.4918, 0.4895, and 0.5107. Treat this as a failed external generalization result, not a reliable detector result. The report remains provisional because the observed counts (3,744 real and 104,200 synthetic frames) differ from the publisher's counts (3,746 and 106,948), the candidate-unit count does not match the publisher's 480 videos, and source mappings have not been reviewed. Each fold used its SDFVD2 validation-selected threshold; no threshold was fitted on the external set.
The personalized Colab handoff notebook expects the Comprehensive archive and completed SDFVD2 five-fold checkpoint directory in the user's Drive, extracts to Colab temporary storage, and writes reports back to Drive. It is intentionally excluded from source bundles and public version control because it contains user-specific Drive paths. Use the CLI command above with your own storage paths, or create a generic Colab notebook that accepts those paths as inputs.
For SDFVD 2.0 on Colab, use the privately customized launcher stored in your Drive. It extracts the dataset and derived features to Colab temporary storage, then saves checkpoints, audit files, splits, predictions, and evaluation metrics to a run-specific Drive folder. Personalized launchers and generated source bundles are excluded from public version control. The hosted notebook runtime must be started from Colab.
The split generator assigns whole group_id values to one split; for single-label source groups it stratifies groups by class, while mixed-label groups use a deterministic group-hash fallback. Exact duplicate content merges inferred source groups before assignment, and duplicate copies are excluded from the split manifests while being recorded in duplicate_records.jsonl. The AV readiness checker and trainer check split isolation again. The trainer selects a checkpoint using fused validation ROC AUC (falling back to validation balanced accuracy if AUC cannot be computed), then writes validation and test predictions. The runner selects a separate decision threshold from validation data and reports held-out test metrics for fused, visual-only, and audio-only ablations; audio-only evaluation uses only videos with decodable audio and is skipped if its validation data cannot support threshold selection. multimodal/initialize.py can save an untrained checkpoint for wiring checks only; scores from it are random and must not be reported as detector results.
The ingestion, splitting, and training steps stream records and images or use disk-backed indexes, so RAM does not need to hold the whole dataset. The dataset still needs sufficient local disk, processing time, and compute, especially for extracted frames and model training. Store source media and derived data in a private local folder that is not automatically synced to a cloud service unless the dataset terms and your privacy requirements allow it. Review source terms and citations before use; public access or competition participation does not grant broader reuse rights. Detector scores are uncertain evidence and must not be treated as proof that a video is authentic or manipulated.
Still-image training path
The frame baseline can train on still-image datasets as well as video frames. Use the same consent, usage, label, source, and group_id metadata with the ingestion step, then create a derived image-frame manifest.
​
The image preparer copies source images without editing them, checks their SHA-256 against the ingestion manifest, and writes one frame per image into a separate derived folder. It does not detect or crop faces. Unknown labels remain in the frame manifest and are excluded by the split generator.
Sharing and Colab configuration
The repository excludes datasets, media, model weights, run outputs, credentials, and generated Colab notebooks. Keep these local or in private storage. The Kaggle handoff notebooks can be regenerated with python multimodal/build_ffpp_c23_validation_notebook.py and python multimodal/build_kaggle_external_notebook.py; edit the generated notebook's BASE and CV_RUN_FOLDER values for your own Drive layout before running. Store Kaggle credentials in Colab Secrets (KAGGLE_USERNAME and KAGGLE_KEY), never in the notebook or repository.
